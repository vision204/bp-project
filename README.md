# Blox Fruits Web Clone — Prototype

블록스피스(Blox Fruits)를 참조해 웹으로 만드는 3D 액션 게임 프로젝트입니다.

## 스택

- **Three.js** — 3D 렌더링
- **Rapier** (`@dimforge/rapier3d-compat`) — 물리/캐릭터 컨트롤러
- **Vite + TypeScript** — 빌드 도구
- **Firebase** (Auth + Firestore) — 구글 로그인 · 클라우드 세이브 · 랭킹 (선택 사항)
- **Node.js + ws** — 멀티플레이 서버(위치 동기화 + PvP 판정, 선택 사항 — `server/`)

## 실행 방법

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:5173` 접속.

프로덕션 빌드: `npm run build` (결과물은 `dist/`)

멀티플레이(다른 플레이어 보기 + PvP)를 같이 켜려면 별도 터미널에서:

```bash
npm run server   # ws://localhost:8787 — 자세한 내용은 "멀티플레이 · PvP" 절 참고
```

## 시작 화면 — ① 진영 ② 모드

접속하거나 F5를 누를 때마다 두 단계를 고릅니다. 키보드로도 됩니다
(1단계 `1`/`2` = 해적/해군, 2단계 `1`/`2`/`3` = 빠른/그냥/개발자).

### 1단계 — 해적 / 해군

**시작 섬만 갈리고, 그 뒤 항로는 양쪽이 완전히 같습니다.**

| | 해적 | 해군 |
|---|---|---|
| 시작 섬 | 🏴‍☠️ 해적 마을 (144, -80) | ⚓ 해군 기지 (-144, 80) |
| 상대하는 몬스터 | 해군 신병 | 해적 잡병 |
| 부활 지점 | 해적 마을 | 해군 기지 |
| 합류 지점 | 정글 섬(Lv.25)부터 완전히 동일 | 〃 |

두 섬은 난이도가 정확히 같고(체력 30 / 경험치 15), 원점을 사이에 두고 마주봅니다.
상대 진영 섬에도 배를 타고 갈 수 있습니다 — 막아두지 않았습니다.

### 2단계 — 빠른 / 그냥 / 개발자

| | 빠른 모드 | 그냥 모드 | 개발자 모드 |
| --- | --- | --- | --- |
| 그림자 | 끔 | 켬 (2048px) | 끔 |
| 안티앨리어싱 | 끔 | 켬 | 끔 |
| 렌더 해상도 | 1배 | 최대 2배 | 1배 |
| 섬 소품 | 45% | 100% | 100% |
| 바다 격자 / 반짝임 | 16 / 끔 | 72 / 켬 | 24 / 끔 |
| 몬스터 표시 거리 | 85m | 130m | **240m** |
| 먼 섬 숨기기 | 420m 밖 숨김 | 항상 표시 | 항상 표시 |
| 비행 · 무적 | — | — | **켜짐** |

GPU 없는 이 컨테이너에서 실측하면 빠른 모드가 그냥 모드보다 **약 2.3배**(3.5 → 8.0fps)
빠릅니다. 실제 GPU가 있는 PC에서는 둘 다 훨씬 부드럽고, 차이는 사양이 낮을수록 커집니다.

설정값은 `src/core/GraphicsSettings.ts` 한 파일에 모여 있습니다. 자동 테스트나 북마크용으로
`?faction=marine&mode=fast`를 붙이면 선택 화면을 건너뜁니다.

시작 화면 마크업은 `index.html`에 직접 넣고 최소 스타일을 인라인으로 붙여두었습니다.
2.5MB짜리 번들이 도착하기 전에도 화면이 바로 뜨고, 고르는 동안 물리 엔진(Rapier WASM)을
백그라운드에서 미리 불러옵니다.

## 개발자 모드 — 날아다니며 둘러보기

섬을 빠르게 돌아보고 피드백하기 위한 모드입니다. 켜지면:

- **비행이 처음부터 켜져 있습니다** (F키로 끄고 켜기). 지형·바다를 그대로 통과하고
  중력이 적용되지 않습니다. 컨트롤러 충돌 판정을 아예 거치지 않고 위치를 직접 옮깁니다.
- **W/S** 는 보는 방향 그대로(위아래 포함) 날아갑니다. **A/D** 수평 이동,
  **Space** 상승, **Ctrl** 하강, **Shift** 가속. 기본 60 m/s, 가속하면 180 m/s라
  바깥 고리 섬(640m)까지 몇 초면 갑니다. 고도 상한은 400m입니다.
- **P키 — 섬 순간이동 패널.** 두 바다의 섬 23개가 바다별로 나뉘어 나오고, 클릭하면
  그 섬 상공 45m로 바로 이동합니다. **두 번째 바다 섬을 눌러도 해적왕 없이 바로 갑니다.**
  섬마다 반지름·몬스터 종류 수·현재 위치에서의 거리가 같이 표시됩니다.
- **피해를 받지 않습니다.** Lv.1900 몬스터 한가운데 떨어져도 죽지 않아서, 고레벨 섬을
  마음 놓고 구경할 수 있습니다. 익사도 없습니다.
- HUD 좌상단에 비행 상태와 실시간 좌표가 표시됩니다.

일반 모드에서는 F·P키가 아무 동작도 하지 않습니다 (검증 스위트가 이걸 확인합니다).

### 만렙 테스트 캐릭터

개발자 모드로 들어가면 **처음부터 만렙 상태**로 시작합니다. 두 번째 바다나 10단 점프를
확인하려고 몇천 마리를 잡을 필요가 없습니다.

| | 값 |
|---|---|
| 레벨 | **Lv.2,050** — 모든 몬스터의 적정 레벨 중 가장 높은 값 |
| 스텟 | 4개 스텟에 1,536씩 **실제로 찍힌 상태** (최대 체력 18,532) |
| 코인 | 🪙 10,000,000 |
| 열림 | 무장색 · 10단 점프 · **두 번째 바다** |
| 소지품 | 요루 · 삼도류 (단축바에 올라간 채) · 배 3종 · 포션 99개씩 |

레벨을 `MAX_LEVEL`(세이브 상한 2,500)이 아니라 2,050으로 잡은 이유: 상한은 "조작된
값을 자르는 선"이라 실제 도달 가능한 레벨보다 넉넉히 위입니다. 여기서 필요한 건
"이 게임을 끝까지 판 사람"이라, **마지막 섬 최상위 종족의 적정 레벨**을 씁니다.
섬을 더 추가하면 이 값도 저절로 따라 올라갑니다.

스텟을 포인트로 주기만 하지 않고 **실제로 찍어두는** 이유도 같습니다. 안 찍으면 최대
체력이 100인 채라, 무적을 끄고 뭔가 테스트하려는 순간 접촉 데미지 1,162짜리 몬스터에게
한 방에 죽습니다.

### ⚠️ 개발자 모드는 저장하지 않습니다

**세이브를 읽지도 쓰지도 않습니다.** 내 진짜 캐릭터가 만렙 테스트본으로 덮어써지는
사고를 원천봉쇄하려고, `SaveManager`를 통째로 잠급니다(`readOnly`).

- Lv.42짜리 세이브가 있는 상태로 개발자 모드에 들어가도 **그 세이브를 무시하고** 만렙으로 시작합니다.
- 개발자 모드에서 `flush()`를 강제로 불러도 **로컬·클라우드 어디에도 쓰지 않습니다.**
- **랭킹에도 올라가지 않습니다.** Lv.2,050짜리 유령이 리더보드를 더럽히지 않습니다.

(검증 스위트가 세이브를 심어두고 실제로 이 세 가지를 확인합니다.)

## 개발자 모드 권한 — 지정한 계정만

개발자 모드는 만렙·무적·비행이 되는 테스트용이라 아무나 들어가면 곤란합니다.
그래서 **두 가지 경우에만** 열립니다.

1. **허용 목록에 있는 구글 계정**으로 로그인했을 때
2. **개발 중인 내 컴퓨터**에서 열었을 때 (`localhost`) — 로그인 없이도 열립니다

### 계정 추가하는 법

`src/core/DevAccess.ts`의 목록에 이메일 한 줄만 넣고 다시 빌드하면 됩니다.

```ts
export const DEV_EMAILS: string[] = [
  "jjapgobrus@gmail.com",
  // "친구계정@gmail.com",   ← 이런 식으로 한 줄씩
];
```

지메일의 **점과 +태그는 자동으로 무시**합니다. `jjapgo.brus+test@gmail.com` 으로
로그인해도 `jjapgobrus@gmail.com` 과 같은 계정으로 인정되므로 한 줄만 적으면 됩니다.
(지메일이 아닌 도메인은 점을 그대로 둡니다 — 다른 사람 주소가 될 수 있으니까요.)

### 권한이 없으면 어떻게 보이나

버튼을 **숨기지 않고 잠근 채로 이유를 적어둡니다.** 없어진 줄 알고 찾아 헤매는 것보다
왜 못 쓰는지 보이는 편이 낫습니다.

```
🛠️ 개발자 모드
🔒 개발자 모드는 지정된 계정만 쓸 수 있습니다. 구글 로그인 후 다시 시도하세요.
```

키보드 3번이나 `?mode=dev` 딥링크로도 우회할 수 없게, 모드를 확정하는 함수 안에서
한 번 더 막습니다.

### 이 검사의 한계 — 솔직하게

**이 판정은 브라우저 안에서 돕니다.** 개발자 도구를 열어 코드를 고칠 줄 아는 사람은
우회할 수 있습니다. 브라우저에 내려간 코드는 전부 사용자 것이라, 클라이언트 검사만으로
완전히 막을 수 있는 건 원래 없습니다. 이건 이 프로젝트의 한계가 아니라 웹의 성질입니다.

그래서 **우회해도 얻을 게 없도록** 만들어 두었습니다.

- 개발자 모드는 서버(Firestore)에 **아무것도 쓰지 않습니다.** 세이브도 랭킹도.
- 남의 데이터는 애초에 못 건드립니다 — `firestore.rules`가 **내 uid 문서만** 쓰기를
  허용하기 때문입니다. 이건 서버에서 강제되는 진짜 방어선입니다.
- 즉 개발자 모드를 뚫어서 할 수 있는 일은 **"자기 화면에서 혼자 만렙으로 둘러보기"**가
  전부입니다. 남에게도 나에게도 영향이 없습니다.

정말로 서버까지 막아야 할 일이 생기면(예: 개발자만 쓰는 관리 기능) 그때는
Firebase **Custom Claims**로 옮겨야 합니다 — 그건 서버가 발급하는 토큰이라 위조할 수
없습니다. 지금 단계에서는 과한 구조라 넣지 않았습니다.

### 조작법

| 키 | 기능 |
|---|---|
| W/A/S/D | 이동 (A=왼쪽, D=오른쪽 — 카메라 기준) |
| **Shift** + 이동 | 질주 (8 → 14 m/s) |
| **Q** | 전방 대쉬 (11m, 쿨다운 3초) |
| 스페이스 | 점프 (설인에게 배우면 공중에서 한 번 더 — 최대 10단) |
| 마우스 우클릭 드래그 | 시점 회전 (누르는 동안 커서가 사라지고 화면에 고정됨) |
| **마우스 휠** | 카메라 확대/축소 (0~28m) — 끝까지 당기면 1인칭 |
| 좌클릭 | 근접 공격 |
| **Z / X / C / V** | 장착한 악마의 열매 스킬 1~4번 |
| **1 / 2 / 3** | 단축바 장비 뽑기 / 집어넣기 |
| E | NPC / 뱃사공 / 설인 / 열매 상인 / **해적왕(바다 이동)** / 배 타기·내리기 |
| H | 무장색 발동 / 해제 |
| I | 인벤토리 열기/닫기 |
| K | 캐릭터(스텟 배분) 열기/닫기 |

> Z/X/C/V가 스킬로 배정되면서 예전에 쓰던 키를 옮겼습니다:
> **무장색 V → H**, **캐릭터창 C → K**.
>
> **상점은 NPC가 없어졌습니다.** 화면 우측 상단의 **🏪 상점** 버튼으로 언제 어디서든 엽니다
> (인벤토리·캐릭터 버튼도 같이 있습니다).
>
> 상점·캐릭터 목록이 길면 아래에 **"▾ 아래로 스크롤"** 표시가 뜹니다. 휠로 내리면
> 나머지 항목(어둠·고무·모래 열매 등)을 볼 수 있습니다.

### 카메라 (마우스 휠)

로블록스처럼 휠로 카메라 거리를 조절합니다. 기본 6m, 범위 0~28m.
한 칸이 바꾸는 거리는 현재 거리에 비례해서 커지므로(멀수록 크게), 가까이서는 미세하게
멀리서는 시원하게 움직입니다. 휠 이벤트의 단위(픽셀/줄/페이지)는 브라우저마다 다르기 때문에
부호만 취해 **"한 칸 = 한 단계"**로 정규화했습니다.

거리를 0까지 당기면 **1인칭**이 되고, 시야를 가리지 않도록 내 캐릭터가 숨겨집니다.
배를 타고 있을 때는 배가 커서 기본 거리가 7m 더 멀지만, 휠 조절은 똑같이 먹힙니다.

### HUD (좌상단 상태창)

**레벨과 경험치를 한 줄로 합쳐 맨 위**에 뒀습니다. `Lv.42` 칩 바로 오른쪽에 경험치 바가
붙어 있어서, "지금 몇 레벨이고 다음까지 얼마나 남았는지"를 한눈에 봅니다.

**모든 바에 실제 숫자를 적습니다.** 길이만 보고 짐작하지 않아도 됩니다.

```
Lv.42  [██████░░░░░░░░░░░░░░]  250 / 1,000 (25%)
HP     [███████████████░░░░░]  300 / 400
MP     [█████░░░░░░░░░░░░░░░]  50 / 200
열매Lv.7[█████░░░░░░░░░░░░░░░]  200 / 800 (25%)

🏴‍☠️ 해적   🪙 1,234,567   🦘 3단 점프   ⚡경험치2배 9:12   무장색 ON
```

아래 배지 줄에는 진영·코인·점프 단수·버프·무장색·대쉬 쿨다운·남은 스텟 포인트가
필요할 때만 나타납니다. 코인은 자릿수를 끊어서(`1,234,567`) 표시합니다.

## 파이어베이스 (로그인 · 클라우드 세이브 · 랭킹)

**설정할 게 없습니다.** 파이어베이스 설정값이 소스(`src/firebase/config.ts`)에 들어 있어서,
받아서 `npm run dev` 하면 바로 로그인 버튼이 나옵니다. Netlify에 올려도 그대로 됩니다.

### 왜 키를 코드에 그냥 넣었나

파이어베이스 웹 설정값(apiKey 등)은 **비밀이 아닙니다.** `.env`에 넣든 코드에 넣든
빌드하면 브라우저 번들에 그대로 실려서 누구나 개발자 도구로 볼 수 있습니다.
파이어베이스 설계 자체가 "이건 공개 식별자이고, 실제 보안은 규칙이 담당한다"입니다.

그래서 `.env`로 감추는 건 **안전을 하나도 더해주지 않으면서** 로컬·Netlify·다른 컴퓨터마다
설정을 다시 해야 하는 번거로움만 만듭니다. 그래서 기본값으로 박아뒀습니다.

실제 방어선은 이 두 가지입니다:

1. **`firestore.rules`** — 세이브는 본인만, 랭킹은 자기 줄만 쓰기 (이미 적용)
2. **App Check** (나중에) — 남이 이 키로 내 프로젝트 할당량을 축내는 것 방지

### 배포한 사이트에서 로그인이 안 될 때 ★ 딱 하나 해야 하는 일

새 주소에 배포하면 파이어베이스가 **모르는 도메인에서 오는 로그인은 막습니다.**
`auth/unauthorized-domain` 에러가 그것입니다. 한 번만 등록해주면 됩니다:

> 파이어베이스 콘솔 → **Authentication → 설정(Settings) → 승인된 도메인**
> → **도메인 추가** → 배포한 주소 입력 (예: `bpproject.netlify.app`)

`localhost`는 처음부터 들어 있어서 로컬 개발은 그냥 됩니다.

### 다른 파이어베이스 프로젝트를 쓰고 싶다면

`.env`로 덮어쓸 수 있습니다. 도우미를 쓰면 편합니다:

```bash
npm run firebase:setup   # 콘솔의 firebaseConfig를 붙여넣으면 .env를 만들어 줍니다
npm run firebase:check   # 잘 들어갔는지 확인
```

`.env`에 값이 있으면 그게 코드의 기본값보다 우선합니다. 일부만 넣어도 되고,
넣지 않은 값은 기본값을 씁니다.

### 처음 한 번만 해두면 되는 콘솔 설정

이미 다 해두셨다면 넘어가세요.

| 단계 | 어디서 |
|---|---|
| 구글 로그인 켜기 | Authentication → Sign-in method → **Google** 사용 설정 |
| 데이터베이스 만들기 | Firestore Database → 데이터베이스 만들기 (위치 `asia-northeast3` 권장) |
| **보안 규칙 붙여넣기** | Firestore Database → 규칙 → `firestore.rules` 내용 붙여넣고 **게시** |
| 배포 도메인 등록 | Authentication → 설정 → 승인된 도메인 → 배포 주소 추가 |

### Netlify 배포

`netlify.toml`이 들어 있어서 깃 저장소를 연결하면 알아서 빌드합니다
(빌드 명령 `npm run build`, 배포 폴더 `dist`). 환경변수는 넣을 필요 없습니다.

수동으로 올리시는 경우엔 `npm run build` 후 생기는 **`dist` 폴더**를 올리면 됩니다.
**코드를 고친 뒤에는 반드시 다시 빌드해서 다시 올려야** 바뀐 내용이 반영됩니다.

> ⚠️ **멀티플레이 서버(`server/`)는 Netlify에 같이 올라가지 않습니다.** Netlify는
> 빌드된 정적 파일(`dist`)만 CDN에서 서빙하는 구조라, 계속 열려 있어야 하는
> WebSocket 서버는 별도로 호스팅해야 합니다. 자세한 내용은 위
> "멀티플레이 · PvP → 서버 실행하기" 절을 참고하세요. 서버를 안 띄워도
> 사이트 자체와 싱글플레이는 지금까지와 똑같이 잘 동작합니다.

### 잘 안 될 때

| 증상 | 원인과 해결 |
|---|---|
| `auth/unauthorized-domain` | 배포 주소를 **승인된 도메인**에 추가하세요 (위 참고) |
| `auth/configuration-not-found` | Authentication에서 **Google 로그인**을 아직 안 켰습니다 |
| `Missing or insufficient permissions` | `firestore.rules`를 붙여넣고 **게시**를 안 눌렀습니다 |
| 팝업이 안 뜸 | 브라우저가 팝업을 막은 경우입니다. 자동으로 리다이렉트 방식으로 넘어갑니다 |
| 배포한 사이트가 옛날 그대로 | 다시 빌드해서 다시 올려야 합니다 (`npm run build` → `dist` 업로드) |

### 무엇이 저장되나

레벨·경험치·코인·스텟·먹은 열매·열매 레벨·무장색 습득 여부·인벤토리·단축바·보유 배·
퀘스트 완료 횟수·뽑기 제한 시각·마지막으로 있던 섬.

최대 체력이나 요구 경험치처럼 **계산으로 나오는 값은 저장하지 않고** 불러올 때 다시 만듭니다.
저장 용량도 줄고, 나중에 밸런스 상수를 고치면 옛 세이브도 새 밸런스를 따라옵니다.

### 언제 저장되나

- 의미 있는 변화가 있을 때 표시해두고 **15초에 한 번**만 실제로 씁니다
  (Firestore는 문서 쓰기 단위로 요금이 붙어서, 매 프레임 저장하면 요금이 샙니다)
- 열매를 뽑으면 **즉시** 저장합니다
- 창을 닫거나 탭을 옮길 때도 저장합니다
- 로그인 상태면 **Firestore + 이 브라우저 양쪽**에 저장합니다.
  인터넷이 잠깐 끊겨도 진행상황이 날아가지 않도록 로컬 백업을 항상 남깁니다.

### 뽑기 4시간 제한과 서버 시각

로그인해서 저장할 때는 뽑기 시각을 **Firestore 서버 시각**(`serverTimestamp()`)으로 씁니다.
컴퓨터 시계를 과거로 돌려도 제한을 우회할 수 없습니다.
로그인하지 않았을 때는 브라우저에 저장하므로, 저장소를 직접 비우면 초기화됩니다.

### 왜 "같은 월드 안의 6km 떨어진 구역"인가

두 바다는 별도의 씬이 아니라, **하나의 월드 좌표계 안에서 6,000m 떨어진 두 구역**입니다.
(첫 번째 바다는 원점, 두 번째 바다는 x+6000)

이렇게 한 이유:

- 섬·몬스터·NPC·퀘스트 배열을 **하나로 유지**할 수 있습니다. `islandAt`, 부활, 세이브,
  퀘스트 카운트 같은 기존 코드가 손댈 필요 없이 그대로 돕니다.
- 헤엄쳐 건너가는 건 6km라 사실상 불가능하고 배도 못 갑니다. **"해적왕이 유일한 통로"라는
  규칙이 물리적으로도 지켜집니다** (검증 스위트가 두 바다 사이 최단 거리를 실제로 잽니다).
- 씬을 통째로 갈아끼우는 방식이 아니라서 **건너갈 때 로딩이 없습니다.** 순간이동 한 번입니다.

대신 두 가지를 바다별로 나눠야 했습니다.

- **안개와 바다 메시**: 두 바다를 통틀어 재면 안개 거리가 6km가 돼서 수평선이 텅 빕니다.
  그래서 각 섬은 자기 바다 원점 기준 좌표(`localCenter`)를 함께 들고 있고, 안개·바다
  크기는 그 값으로 계산합니다. 바다 메시도 바다마다 하나씩 띄웁니다.
- **햇빛**: 예전에는 태양이 월드 원점에 고정돼 있고 그림자 범위가 ±110m였습니다.
  사실 이건 **원래도 버그**여서, 시작 섬을 조금만 벗어나면 그림자가 통째로 사라졌습니다.
  이번에 태양이 플레이어를 따라다니게 고쳤습니다 — 어느 바다 어느 섬에서든 같은 그림자가 나옵니다.

### Lv.400 이상 섬 — 다단 점프 고원 + 중앙 랜드마크

수정 섬(Lv.400)부터 대저택(Lv.1900)까지, 두 바다에 걸친 **13개 고레벨 섬**은
섬 중앙에 높이 7m짜리 절벽형 고원이 추가로 솟아 있습니다. 기존 해변·부두·
몬스터 배치는 그대로고, 고원은 그 위에 "얹힌" 구조라 배를 타고 도착하는
길이나 사냥터에는 아무 영향이 없습니다.

- **왜 7m인가** — 점프 물리(초기 속도 9, 중력 20)로 계산하면 한 단 점프의
  이론상 최대 상승량은 약 2m이고, 정점에 맞춰 눌러야 하는 실전 플레이라면
  한 단당 대략 1.5m 안팎이 나옵니다. 그러면 4단 점프(약 6m)로는 못 넘고,
  5단 점프(약 7.5m, 설인에게 Lv.425부터 배울 수 있음)라야 겨우 넘을 수
  있는 높이가 7m입니다 — 절벽을 붙잡고 옆으로 이동하며 여러 번 이어
  뛰어야 꼭대기에 닿습니다.
- **고원 위에는 섬마다 어울리는 커다란 조형물**이 하나씩 서 있습니다: 수정
  섬은 거대 수정 결정 무리, 심연 섬은 검은 오벨리스크, 천공 섬은 구름 위
  황금 파고다, 용의 둥지는 화산분화구, 장미 왕국·얼음 성·대저택은 각각
  성(城), 초원 지대는 커다란 고목, 공동묘지는 영묘, 눈 덮인 산은 설산
  첨봉, 화염과 얼음은 절반씩 나뉜 화산분화구·얼음 첨탑, 저주받은 배는
  좌초한 유령선, 잊혀진 섬은 계단식 폐신전입니다. 순전히 장식이라 사냥·
  퀘스트 진행에는 필요 없고, 올라가면 경치를 볼 수 있는 보너스 구조물입니다.

## 중앙 교역섬 — 마을 + 열매를 사는 두 가지 방법

두 진영 시작 섬 정확히 가운데에 있는 **중립 지대**입니다. 몬스터도 토벌 의뢰도 없고,
코드에서는 `kind: "hub"`인 유일한 섬이라 몬스터 배치와 퀘스트 생성 로직이 이 섬을 건너뜁니다.

### 마을 (2~3층 건물)

돌 포장 광장을 **2~3층짜리 작은 건물 10채**가 둘러싸고 있고, 한가운데에는 분수가 있습니다.
건물은 층마다 벽 색이 살짝 다르고 층 사이에 띠가 있어서 2층집인지 3층집인지 바로 보입니다.
위층으로 갈수록 조금씩 좁아지고, 지붕은 4각뿔에 색이 랜덤(빨강/갈색/파랑/초록)입니다.

**안으로는 들어갈 수 없습니다.** 문과 창문은 벽에 붙인 판때기이고, 건물 전체에 네모난
충돌체가 있어서 통과하지 못하고 옆으로 돌아가게 됩니다. 분수도 막혀 있어서 위로 올라설 수 있습니다.
(나중에 실내를 만들 거라면 이 충돌체를 벽 4개로 쪼개고 문 자리만 비우면 됩니다.)

건물은 부두 방향과 열매 상인 자리를 피해 배치했기 때문에 배 타러 가는 길이나
상인에게 가는 동선은 막히지 않습니다.

### 열매를 사는 두 가지 방법

| | 중앙섬 열매 상인 | 화면 우측 🏪 상점 |
|---|---|---|
| 결제 수단 | **게임 화폐(코인)** | **현금(원화)** |
| 가는 법 | 중앙 교역섬에서 **E** | 아무 데서나 버튼 클릭 |
| 가격 | 🪙70 ~ 🪙150 | ₩3,400 ~ ₩7,900 |
| 실제 동작 | 코인 차감 후 즉시 지급 | **없음 — 표시만** |

> ⚠️ **현금 결제는 아직 기능이 없습니다.** PG사 연동 전이라 결제창을 띄우거나 아이템을
> 지급하는 코드가 아예 들어 있지 않습니다. 버튼을 눌러도 "준비 중" 안내만 뜨고,
> 코인도 차감되지 않고 열매도 지급되지 않습니다.
> `ShopSystem.ts`의 `CASH_PAYMENT_ENABLED = false`가 그 표시이고, 검증 스위트가
> 이 값이 꺼져 있는지 + 눌러도 아무것도 안 지급되는지를 확인합니다.
> 나중에 PG사와 계약하면 이 플래그와 버튼 핸들러만 실제 결제로 바꾸면 됩니다.

코인 가격과 원화 가격의 **순서는 항상 일치**합니다(검증 스위트가 확인). 즉 코인으로 비싼
열매는 현금으로도 비싸서, 두 창구 사이에 밸런스가 어긋나지 않습니다.

## 열매 뽑기 — 정글 섬 도박사 (전 재산의 30% · 4시간에 1회)

항해 순서상 **두 번째 섬인 정글 섬**에 "열매 도박사"가 있습니다. 코인을 걸면 무작위 열매가
나오고, 나온 열매는 그 자리에서 바로 장착됩니다.

- **참가비 = 지금 가진 코인의 30%** (내림). 부자일수록 비싸집니다.
  - 코인이 0이면 참가비도 0이 되는 허점을 막기 위해 **최소 참가비 🪙20**을 두었고,
    그래서 뽑으려면 최소 **🪙67**(20 ÷ 0.3)은 있어야 합니다.
- **4시간에 한 번**. 남은 시간이 패널과 버튼에 그대로 표시됩니다.
- **새로고침해도 제한이 유지됩니다.** 마지막으로 뽑은 시각을 브라우저에 저장하기 때문에
  F5로 우회할 수 없습니다 (`core/Persistence.ts`). 시스템 시계를 과거로 돌려도 막힙니다.
- **비싼 열매일수록 잘 안 나옵니다.** 가중치 = (최고가 ÷ 그 열매 가격)^1.5 이라,
  모래 열매 29.3% ↔ 어둠 열매 9.4%로 약 3배 차이가 납니다.
  확률은 숨기지 않고 패널에 막대그래프로 그대로 보여줍니다.

시간은 `GachaSystem`이 직접 읽지 않고 항상 `nowMs`를 인자로 받습니다. 덕분에 테스트에서
"4시간 뒤"를 마음대로 만들어 검증할 수 있고, 나중에 서버 권위 방식으로 옮길 때 서버 시계를
그대로 넘기면 됩니다.

## 섬 가이드 (🧭 버튼)

화면 우측의 작은 **🧭 섬 가이드** 버튼을 누르면 갈 만한 섬 목록이 뜹니다.

- 맨 위에 **내 레벨에 맞는 추천 사냥터**와 **다음 목표**(몇 레벨 남았는지)를 알려줍니다.
  추천은 "의뢰를 받을 수 있는 섬 중 가장 높은 곳" 기준입니다.
- 섬마다 요구 레벨, 현재 위치에서의 거리가 나오고, 아직 못 가는 섬은 흐리게 표시됩니다
  (상륙은 자유지만 의뢰를 못 받는다는 안내도 함께).
- 상대 진영 시작 섬은 목록에서 빠집니다.
- **길 안내**를 누르면 창이 닫히고 화면 위쪽에 **방향 화살표 + 남은 거리**가 뜹니다.
  화살표는 "지금 카메라가 보는 방향" 기준이라, **화살표가 위를 가리키면 그대로 직진**하면 됩니다.
  시점을 돌리면 화살표도 같이 돌아갑니다.
- 목적지에 닿으면 안내가 **자동으로 꺼지고** 도착 알림이 뜹니다. 도중에 ✕로 취소할 수도 있습니다.

## 몬스터 종류 — 레벨 차이 50당 한 종류

다음 단계 섬과 필요 레벨이 많이 벌어지는 섬은 한 종류만 잡으면 단조로워지므로,
**다음 섬과의 레벨 차이 50당 몬스터를 한 종류씩** 배치했습니다.

| 섬 | 다음 섬까지 | 종류 | 몬스터 (적정 레벨) |
|---|---|---|---|
| 안개 섬 | 100 | 2 | 안개 유령(300) · 저주받은 선장(350) |
| 수정 섬 | 150 | 3 | 수정 골렘(400) · 수정 파수꾼(450) · 수정 군주(500) |
| 심연 섬 | 150 | 3 | 심연 촉수(550) · 심연 사냥꾼(600) · 심연 포식자(650) |
| 천공 섬 | 200 | 4 | 천공 사제(700) · 기사(750) · 대장(800) · 수호신(850) |
| 용의 둥지 | — | 4 | 새끼(900) · 화염(950) · 폭풍(1000) · 고룡(1050) 드래곤 |

레벨 차이가 100 미만인 섬(시작~폭풍)은 예전처럼 한 종류입니다.

각 종족은 **"섬 요구 레벨 + 50 × 단계"**를 적정 레벨로 잡습니다. 그래서 한 섬 안에서
1단계 → 마지막 단계로 옮겨가며 사냥하면 다음 섬 요구 레벨까지 그대로 올라갑니다.
수치는 손으로 적지 않고 1단계 기준값에서 계산합니다 — 체력 ×1.28, 접촉 피해 ×1.22,
코인 ×1.35씩 오르고, 경험치는 그 단계의 적정 레벨에서 다시 `레벨업 요구량 ÷ 8`로 뽑습니다.

**서식지도 갈립니다.** 부두 반대편의 넓은 호를 종족 수만큼 부채꼴로 나누고, 약한 종족은
섬 안쪽(반지름의 34%), 강한 종족일수록 바깥쪽(최대 68%)에 배치했습니다. 종류마다 색과
크기가 다르고 머리 위에 **이름표**가 붙어서, 퀘스트에서 고른 몬스터를 눈으로 바로 찾을 수 있습니다.

### 퀘스트에서 사냥할 몬스터 고르기

몬스터가 두 종류 이상인 섬에서 토벌대장에게 **E**를 누르면 바로 수락되지 않고
**선택 창**이 열립니다. 종류마다 권장 레벨·체력·경험치·코인이 표시되고, 내 레벨보다
40 이상 높은 종류에는 빨간 경고가 붙습니다. 고른 종류만 카운트되므로, 같은 섬에서
다른 종류를 아무리 잡아도 진행되지 않습니다. 한 종류뿐인 섬은 예전처럼 E 한 번에 수락됩니다.

### 레벨 제한은 "퀘스트"에만 걸립니다

**섬에 상륙하는 것 자체는 레벨과 무관하게 자유롭습니다.** Lv.1로도 배를 몰고
용의 둥지까지 갈 수 있어요. 대신 그 섬의 **토벌대장이 의뢰를 주지 않습니다**.

> 용의 둥지 토벌대장: *"아직 자네에겐 무리야. Lv.900 이상이어야 의뢰를 줄 수 있네"*

몬스터도 그 레벨대에 맞게 강하기 때문에, 무리해서 올라가면 접촉 데미지만으로도
금방 쓰러집니다. 구경은 자유, 사냥은 실력껏인 구조입니다.

### 난이도 밸런스

몬스터 경험치는 **"그 종족의 적정 레벨에서 1레벨 올리는 데 필요한 경험치 ÷ 8"** 기준으로
잡았습니다. 어느 구간에 가도 대략 몬스터 8~15마리에 1레벨이 올라서, 새 섬(또는 같은 섬의
다음 단계 몬스터)으로 넘어갔을 때 체감 속도가 비슷하게 유지됩니다. 퀘스트(7마리 처치 → 그 레벨의 90%)까지 끼면
Lv.900까지 약 1,000회 정도의 의뢰 분량입니다.

### 배 등급 (비쌀수록 빠름)

상점 **배** 코너에서 더 빠른 배를 살 수 있습니다. 소환하면 **보유 중 가장 좋은 배**가 나옵니다.

| 배 | 가격 | 최고 속도 | 선회 |
|---|---|---|---|
| ⛵ 낡은 돛단배 | 기본 제공 | 18 m/s | 1.5 |
| 🚤 쾌속정 | 🪙450 | 32 m/s | 2.1 |
| 🛥️ 질풍호 | 🪙1,600 | 48 m/s | 2.7 |

질풍호는 기본 배의 **2.7배 속도**라 바깥 고리 섬(640m)까지 훨씬 빨리 갑니다.
선체·돛 색도 등급별로 달라집니다.

### 항해 방법

섬마다 부두와 뱃사공 NPC가 있습니다. 뱃사공에게 **🪙5**(아주 저렴)로 배를
사면 부두 끝에 배가 소환됩니다. 배에 다가가 **E**를 누르면 탑승하고, 그때부터
**WASD로 직접 배를 몰면서 바다를 자유롭게 탐험**합니다.

- **W/S** 전진·후진 (최고 18 m/s), **A/D** 선회, **E** 내리기
- 섬 근처에서 내리면 자동으로 해안에 상륙하고, 먼 바다에서 내리면 물에 빠집니다
- 목적지를 고르는 창이 없습니다. 그냥 배를 몰고 가면 어느 섬이든 상륙할 수 있습니다
- 배는 사라지지 않고 내린 자리에 그대로 있습니다. 멀리 두고 왔다면 아무 섬 뱃사공에게
  🪙5를 내고 그 부두로 다시 부를 수 있습니다
- 배를 타고 있는 동안에는 익사하지 않습니다

**바다**: 섬 밖은 전부 바다입니다. 물에 빠지면 수면에 뜬 채로 **초당 6씩 체력이 깎이며**,
버티지 못하면 가까운 섬에서 부활합니다. 섬 가장자리에는 완만한 해변이 있어서 제때
헤엄쳐 돌아오면 걸어 올라올 수 있습니다.

## 악마의 열매 스킬 (6종 × 4개 = 24개)

열매마다 **Z / X / C / V** 네 개의 스킬이 있고, **열매 레벨**로 순서대로 해금됩니다.

| 슬롯 | 해금 열매 레벨 |
|---|---|
| Z | 1 (기본) |
| X | 25 |
| C | 50 |
| V | 100 |

### 열매 레벨 — 캐릭터 레벨과 완전히 별개

**마지막 타격(막타)을 열매 스킬로 넣었을 때만** 열매 경험치가 오릅니다.
근접 공격으로 마무리하면 캐릭터 경험치만 들어오고 열매 경험치는 **0**입니다.
(열매 스킬이 건 화상 같은 지속 피해로 죽는 것도 "열매 막타"로 인정됩니다.)
열매 레벨 1당 모든 열매 스킬 데미지가 **+2%** 오릅니다(100레벨이면 약 3배).

### 스킬 목록

| 열매 | Z | X (Lv.25) | C (Lv.50) | V (Lv.100) |
|---|---|---|---|---|
| 🔥 마그마 | **마그마 피스트**<br/>주변 원형 25 | **화염 방사**<br/>전방 부채꼴 32 + 화상 | **용암 지대**<br/>원형 34 + 강한 화상 | **대분화**<br/>초광역 90 + 화상 |
| ❄️ 얼음 | **아이스 랜스**<br/>직선 관통 20 + 둔화 | **서리 발판**<br/>원형 24 + 지속 둔화 | **빙결 감옥**<br/>원형 30 + 강한 속박 | **절대 영도**<br/>초광역 80 + 둔화 |
| ⚡ 번개 | **선더 스트라이크**<br/>원형 15, 쿨 1.2초 | **뇌광 질주**<br/>12m 돌진 + 관통 22 | **낙뢰**<br/>원형 38 + 감전 | **천벌**<br/>초광역 85 + 감전 |
| 🌑 어둠 | **다크 슬래시**<br/>부채꼴 24 | **암흑 흡수**<br/>원형 28 + 체력 8% 회복 | **블랙홀**<br/>원형 45 + 속박 | **영원한 어둠**<br/>초광역 110 + 20% 회복 |
| 🥊 고무 | **고무 권총**<br/>직선 18 | **고무 로켓**<br/>14m 돌진 + 관통 20 | **개틀링**<br/>넓은 부채꼴 42 | **기어 세컨드**<br/>12초간 열매 데미지 1.8배 |
| 🏜️ 모래 | **모래 절단**<br/>부채꼴 18 | **사막의 검**<br/>직선 26 + 지속 피해 | **모래 폭풍**<br/>원형 30 + 둔화 | **사막의 대검**<br/>초광역 95 + 지속 피해 |

판정 모양은 4가지입니다.

- **원형(radial)** — 플레이어 주변 전 방향
- **부채꼴(cone)** — 카메라가 보는 방향으로 퍼짐
- **직선(line)** — 보는 방향으로 뻗으며 경로상의 적을 전부 관통
- **자기 강화(self)** — 적을 직접 때리지 않고 자신을 버프

부채꼴·직선 스킬은 **카메라가 보는 방향**으로 나갑니다(이동 방향이 아닙니다).
우클릭 드래그로 조준하세요.

## 무기 — 흑도 "요루" / 삼도류 / 엔마

### 흑도 "요루" (상점 · 🪙800)

상점 **무기** 코너에서 🪙800에 살 수 있는 칠흑빛 대검입니다.
**로블록스처럼 2단계로 장착**합니다.

1. **인벤토리(I)에서 클릭** → 화면 하단 중앙 **단축바**에 올라갑니다 (1차 장착).
   이때는 아직 손에 들지 않은 상태이고, 장비는 소모되지 않고 인벤토리에 그대로 남습니다.
2. **숫자키 1번을 누르면** 실제로 칼을 뽑아 손에 듭니다. 같은 키를 다시 누르면 집어넣습니다.

뽑은 상태에서는 **근접 공격력 2.6배**, **사거리 +1.6m**가 적용되고 캐릭터가 실제로
검은 대검을 들고 있는 모습으로 바뀝니다. 무장색(H)과는 곱연산으로 함께 적용돼서,
둘 다 켜면 근접 데미지가 **3.64배**가 됩니다.

단축바는 3칸이라 나중에 무기를 더 추가해도 2·3번 키로 바로 확장됩니다.

### 삼도류 (설인 · 🪙2,500) — 얼음 섬에서만

칼 세 자루를 양손과 입에 무는 검술입니다. **상점에서는 팔지 않고**, 얼음 섬(Lv.125)의
**설인**에게만 살 수 있습니다.

| | 요루 | 삼도류 | 엔마 |
|---|---|---|---|
| 공격력 | ×2.6 | **×2.9** | ×2.3 |
| 사거리 | +1.6m | +1.2m | **+2.0m** |
| 공격 간격 | 그대로 (0.50초) | **0.325초 (35% 빠름)** | 0.45초 (10% 빠름) |
| 값 | 🪙800 | 🪙2,500 | 🪙700 |

사거리는 요루보다 짧지만 **초당 데미지(DPS)는 약 1.7배**입니다. 붙어서 난타하는 무기라고
보면 됩니다. 장착 방법은 요루와 같습니다 (인벤토리 클릭 → 단축바 → 숫자키).
손에 들면 캐릭터가 **양손에 한 자루씩, 입에 한 자루**를 문 모습으로 바뀝니다.

### 엔마 (화산 섬 전용 · 🪙700)

화산 섬(Lv.200)에서만 살 수 있는 붉고 얇고 긴 장검입니다. **상점 목록에는 다른 섬에서도
그대로 보이지만**, "여기서는 못 산다"는 걸 숨기지 않고 버튼에 그대로 보여줍니다 — 화산 섬에
있을 때만 구매 버튼이 열리고 실제로 살 수 있습니다.

공격력은 요루보다 낮지만 **사거리가 세 무기 중 가장 깁니다**(+2.0m). 얇고 가벼운 만큼
공격 속도도 요루보다 살짝 빠릅니다. 멀리서 견제하듯 싸우는 무기라고 보면 됩니다.
장착 방법은 요루·삼도류와 같습니다 (인벤토리 클릭 → 단축바 → 숫자키).
손에 들면 캐릭터가 요루와 같은 자리(오른손)에, 훨씬 얇고 긴 붉은 칼날을 든 모습으로 바뀝니다.

## 설인 — 얼음 섬(Lv.125)의 사범

얼음 섬에 있는 NPC **설인**은 한 자리에서 세 가지를 가르칩니다. E로 말을 걸면 한 창에
세 줄이 뜨고, **못 배우는 것도 숨기지 않고 "무엇이 모자란지"를 그대로 보여줍니다**
(레벨이 부족한지, 코인이 부족한지).

| 배우는 것 | 조건 | 값 |
|---|---|---|
| 삼도류 | 없음 | 🪙2,500 |
| 무장색 | 없음 | 🪙300 |
| 다단 점프 | Lv.125부터, 이후 100레벨마다 한 단계 | 1,200 × 1.8^(단계-2) |

### 다단 점프 — 100레벨마다 한 단씩

- **Lv.125**에 2단 점프를 배웁니다.
- 그 뒤로는 **레벨이 100 오를 때마다 설인을 다시 찾아가면** 한 단씩 더 배웁니다.
  (Lv.225 → 3단, Lv.325 → 4단, … **최대 10단**)
- 수업료는 단계마다 1.8배씩 오릅니다. 2단 🪙1,200 · 3단 🪙2,160 · 4단 🪙3,888 …
- 공중에서 스페이스를 다시 누르면 그 자리에서 위로 다시 솟구칩니다. 땅에 닿는 순간
  사용 횟수가 초기화됩니다. 배를 타거나 순간이동해도 초기화됩니다.
- 배운 단수는 HUD 좌상단에 **🦘 N단 점프** 배지로 표시되고, 세이브에 저장됩니다.

> 무장색은 사막 섬의 무장색 사범에게도 그대로 배울 수 있습니다. 설인은 "얼음 섬까지
> 왔는데 아직 안 배웠다면" 여기서도 배울 수 있게 열어둔 두 번째 창구입니다.

## 성장 시스템

- **레벨업**마다 스텟 포인트 3개 지급 → **마나 / 공격력 / 체력 / 열매** 4개 스텟에 자유 배분(K키).
  체력 → 최대체력(+12), 마나 → 최대마나(+8)·마나회복, 공격력 → 근접 데미지(+2),
  열매 → 악마의 열매 능력 데미지 배율(+8%).
- **악마의 열매는 한 번에 하나만** 먹을 수 있습니다. 상점에서 5종(얼음/번개/어둠/고무/모래)을
  팔지만, 새로 먹으면 기존 열매 능력은 사라지고 교체됩니다.
  **열매 레벨은 캐릭터의 숙련도라서 열매를 바꿔도 유지됩니다.**
- **경험치 2배 포션**(🪙20): 10분 동안 획득 경험치가 2배. 상점에서 사서 인벤토리(I)에서
  클릭해 사용합니다. HUD에 남은 시간이 표시됩니다.
- **회복 포션**(🪙15): 체력 50 회복.
- **섬 퀘스트**: **11개 섬 전부에 토벌대장 NPC**가 한 명씩 있고, 그 섬의 몬스터를
  **7마리 처치**하면 **현재 레벨에 필요한 경험치의 90%를 즉시** 받습니다.
  단, **그 섬의 필요 레벨을 넘어야 의뢰를 받을 수 있습니다.**
  보상이 고정값이 아니라 비율이라 레벨이 올라가도 계속 의미가 있습니다.
  **반복 수행 가능**하며, 킬 카운트는 **그 섬 몬스터만** 인정됩니다
  (다른 섬에서 잡은 건 카운트되지 않습니다).
- **무장색(武)**: **3번째 섬인 사막 섬**의 "무장색 사범", 또는 **얼음 섬의 설인**에게
  🪙300을 내고 배웁니다.
  말을 걸면 배울지 **예/아니오**로 묻고, 배우면 **H키**로 발동할 수 있습니다.
  발동하면 **전신이 검게** 변하고 근접 공격 데미지가 **+40%** 오릅니다.
  대신 발동 중에는 마나가 초당 2.5씩 줄고 **자연 회복이 멈추며**, 마나가
  바닥나면 자동으로 해제됩니다.

레벨 곡선은 `40 + level^1.6 × 6` 다항식입니다. (예전 1.35배 지수 곡선은 50레벨에
1억 경험치가 필요해 사실상 도달 불가능했습니다.) 지금은 235레벨까지 누적 약 336만 경험치로,
최상위 섬 몬스터 기준 약 560킬이면 만렙에 도달합니다.

## 멀티플레이 · PvP

화면 우측 **🌐 멀티플레이** 버튼으로 서버에 접속하면, 같은 서버에 접속한 다른
플레이어가 실제로 움직이는 게 보이고, **다른 진영끼리는** 서로 때릴 수 있습니다
(해적 ↔ 해군 — 같은 진영은 공격이 서버에서 아예 거부됩니다).

### 왜 "몬스터·퀘스트·상점까지 통째로 서버로 옮기지" 않았나

"구조" 절에 적었듯 이 프로젝트는 처음부터 시뮬레이션(게임 로직)과 렌더링을
분리해뒀습니다 — **언젠가 `simulation/`을 그대로 서버로 옮겨서 서버 권위
멀티플레이를 만들 수 있도록**요. 그런데 몬스터 AI·퀘스트·상점·항해까지 전부
서버 시뮬레이션으로 옮기는 건 지금 있는 싱글플레이 게임 전체를 다시 설계하는
일이라, 기존의 600여 개 로직 검증과 400여 개 브라우저 검증이 통째로 다시
필요해집니다. 그래서 오늘은 **훨씬 얇은 레이어**를 택했습니다.

- **몬스터·퀘스트·상점·항해·세이브는 지금처럼 각자 클라이언트에서 그대로
  돌아갑니다.** CombatSystem.ts는 여전히 몬스터만 알고, 다른 플레이어의
  존재를 전혀 모릅니다. 그래서 싱글플레이 동작과 기존 검증 스위트가 한 줄도
  안 바뀝니다.
- 서버가 하는 일은 딱 둘입니다: **① 누가 어디 있는지 서로 뿌려주기**(presence),
  **② PvP 공격이 들어오면 "진짜로 맞았는지" 서버가 다시 계산해서 판정하기**.
- 판정 계산은 `src/simulation/CombatSystem.ts`의 `totalMeleeDamage`/`skillDamage`를
  **서버가 그대로 다시 호출**합니다 — 새 공식을 만들지 않았습니다. `verify-logic.mjs`가
  검증하는 것과 똑같은 순수 함수들이 Node 서버에서도 그대로 돌아갑니다.
  스킬 판정 모양(원형·부채꼴·직선) 계산도 `src/simulation/ShapeMath.ts`로
  빼서 클라이언트(공격 후보 필터링)와 서버(진짜 판정)가 **같은 코드**를 씁니다.

### 서버 실행하기

Netlify는 정적 사이트만 올라가므로(빌드해서 `dist`를 CDN에 올리는 방식),
계속 열려 있어야 하는 WebSocket 서버는 **따로** 띄워야 합니다.

```bash
npm run server        # ws://localhost:8787
# 또는 파일을 고칠 때마다 자동 재시작:
npm run server:dev
```

- 같은 컴퓨터·같은 네트워크에서 테스트할 때는 이걸로 충분합니다.
- 인터넷 너머 친구와 같이 하려면 이 서버를 Render / Fly.io / Railway 같은 곳이나
  직접 가진 VPS에 올리세요. `server/index.ts`는 순수 Node.js + `ws` 패키지라
  대부분의 Node 호스팅에서 그대로 돌아갑니다(헬스체크용 `/healthz` 경로도
  있습니다). 포트는 `PORT` 환경변수로 바꿀 수 있습니다(기본 8787).
- 서버를 올렸으면 게임 화면의 멀티플레이 패널에 그 주소(`wss://...`)를 넣고
  접속하면 됩니다. `.env`의 `VITE_MULTIPLAYER_URL`을 채워두면 그 주소가
  기본값으로 미리 채워집니다.
- 실제 배포 서버: `wss://bp-project-server.onrender.com` (Render 무료
  플랜 — 15분간 아무도 없으면 잠들고, 다음 접속 때 30~60초 정도 깨어나는
  시간이 걸립니다. 헬스체크: `https://bp-project-server.onrender.com/healthz`).

#### Netlify에서 자동 접속되게 하기

패널을 열고 매번 서버 주소를 입력하는 대신, 사이트에 들어가자마자 자동으로
붙게 하려면 Netlify 사이트 설정 → **Site configuration → Environment
variables**에 아래 둘을 추가하고 다시 배포하면 됩니다.

```
VITE_MULTIPLAYER_URL=wss://bp-project-server.onrender.com
VITE_MULTIPLAYER_AUTOCONNECT=1
```

`VITE_MULTIPLAYER_AUTOCONNECT`가 없으면(로컬 개발·검증 스위트가 그렇습니다)
기존과 동일하게 버튼을 눌러야만 접속합니다 — 자동 접속은 이 두 값이 **둘 다**
설정된 빌드에서만 켜집니다.

### 접속하고 PvP 켜기

1. **🌐 멀티플레이** 버튼 → 서버 주소·이름 입력 → **접속**.
2. 접속되면 근처 다른 플레이어 목록(진영·레벨·체력)이 보입니다.
3. **⚔️ PvP 켜기** 체크박스는 **기본으로 켜진 상태**로 시작합니다(접속만 해도
   서로 공격 가능). 필요하면 언제든 꺼둘 수 있고, 공격/피격이 성립하려면
   **양쪽 다** 켜져 있어야 합니다.
4. 진영이 다르면 당연히 싸울 수 있고, **해적끼리는 같은 진영이어도 서로
   싸울 수 있습니다**(해적 나라의 무법자 정서에 맞춰 열어둔 예외입니다).
   다만 **해군끼리는 여전히 서버가 시도 자체를 받아주지 않습니다**
   (`same_faction` 거부) — 정돈된 해군 조직 안에서 동료를 공격하는 건
   허용하지 않는다는 설계입니다.
5. 사거리 안에서 좌클릭(근접)이나 Z/X/C/V(열매 스킬)를 쓰면, 싱글플레이 때와
   똑같은 판정 범위 안에 PvP가 켜진, 공격 가능한(다른 진영이거나 둘 다
   해적인) 플레이어가 있는지 확인해서 서버로 공격을 보냅니다. 서버가
   승인하면 상대 화면에서 실제로 체력이 줄고, 내 화면에는 "⚔️ 피해 N!"
   토스트가 뜹니다.
6. 체력이 0이 되면 싱글플레이와 같은 부활 로직으로 가까운 섬에서 되살아납니다.

멀티플레이는 **완전히 선택 사항**입니다. 버튼을 누르지 않으면 소켓을 아예
열지 않고, 나머지 모든 동작은 지금까지와 똑같습니다.

### 신뢰 경계 — 솔직하게

> ⚠️ 앞서 개발자 모드·현금 결제·랭킹에서도 그랬듯, 여기서도 한계를 숨기지
> 않습니다.

- **내 hp는 내 클라이언트만 바꿀 수 있습니다.** 브라우저 게임의 근본적인
  한계라, 다른 사람이 내 화면의 상태를 직접 바꿀 방법이 없습니다. 그래서
  "내가 맞았다"는 서버의 판정(`pvp_damage`)을 받으면, **내 클라이언트가
  스스로** hp를 깎습니다. 개발자 도구로 이 메시지 처리를 막아버리면 이론상
  무적이 될 수 있습니다 — 이건 이 프로젝트의 한계가 아니라, 서버 시뮬레이션
  없이 순수 클라이언트 게임으로 PvP를 붙일 때 생기는 웹의 성질입니다.
- **데미지 계산은 서버가 하지만, 계산에 쓰는 스텟(공격력·무기·무장색 등)은
  클라이언트가 주기적으로 보고한 값입니다.** 그 값을 부풀려 보내면 실제보다
  센 공격을 날릴 수 있습니다. 그래서 마지막 방어선으로 `server/state.ts`가
  상식적인 상한선(예: 근접 데미지 20,000 이상은 자름)을 한 번 더 잘라내지만,
  **완전한 부정행위 방지는 아닙니다.**
- 그래도 서버가 확실히 막는 것들이 있습니다: **사거리 밖 공격**(위치는 서버가
  직접 추적), **쿨다운 무시**(스킬별 쿨다운을 서버가 직접 잽니다), **해군끼리의
  같은 진영 공격**(해적끼리는 예외로 허용), **PvP 꺼둔 상대 공격**. 이 넷은
  클라이언트가 뭐라고 보고하든 서버가 독립적으로 재계산해서 막습니다.
- 정말로 완전한 서버 권위가 필요해지면(예: 랭킹처럼 돈이 걸린 서비스로
  키운다면), `simulation/`의 나머지 시스템(이동·몬스터·인벤토리)까지 서버로
  옮기고 클라이언트는 렌더링만 하게 바꿔야 합니다 — 지금 구조가 그 방향으로
  가기 쉽게 짜여 있지만, 지금 단계에서는 과합니다.

### 방(room) — 한 방에 최대 14명

서버 프로세스 하나 안에 방이 여러 개 있습니다. 접속하면 자리가 있는(14명
미만) 가장 앞 번호 방(`room1`, `room2`, …)에 자동으로 들어가고, 그 방이
꽉 차면 새 방이 자동으로 생깁니다. **같은 방 사람들끼리만** 서로 보이고
PvP도 같은 방 안에서만 됩니다 — 다른 방 사람에게는 공격 자체가
`different_room`으로 거부됩니다. 방을 직접 고르는 기능은 없고, 어느 방에
배정됐는지는 멀티플레이 패널 상단(예: "✅ room2 — 5명과 함께 플레이 중")에서
확인할 수 있습니다.

### 몬스터(NPC) 동기화 — 남이 쫓기는 것도 보임

몬스터는 여전히 각 클라이언트가 로컬로 시뮬레이션합니다(퀘스트·전투 판정은
그대로 유지). 다만 섬마다 몬스터 배치가 결정론적이라 **몬스터 id
(`${species.id}_enemy_${i}`)가 모든 클라이언트에서 항상 똑같다**는 점을
이용해, "지금 내가 어그로를 끌고 있는" 몬스터의 위치·체력만 골라 같은 방에
초당 8회 보고합니다. 서버는 계산 없이 그대로 중계하고(PvP처럼 판정할 게
없는 순수 시각 정보라서요), 받는 쪽은 화면에 그릴 때만 그 위치를 씁니다 —
2.5초 넘게 갱신이 없으면(추적을 그만뒀거나 상대가 나감) 알아서 사라집니다.
내가 그 몬스터를 직접 어그로 끌고 있는 동안에는 항상 내 로컬 시뮬레이션을
우선합니다 — 다른 사람 보고 때문에 내가 때리는 몬스터 위치가 흔들리면
안 되니까요.

### P2P 거래·선물 — 상대에게 우클릭

같은 방의 다른 플레이어에게 마우스를 올리면(테두리 효과로 대상이 표시됩니다)
**짧게 우클릭**해서 "거래하기 / 선물 주기" 메뉴를 띄울 수 있습니다. 기존
우클릭-드래그 카메라 회전과 겹치지 않도록, 누른 채로 크게 움직이면(드래그)
메뉴가 뜨지 않고 그대로 카메라만 돌아갑니다 — 짧게 누르고 뗄 때만 메뉴가
열립니다.

- **거래하기**: 상대에게 거래를 걸어도 곧바로 거래창이 열리지 않습니다 —
  상대 화면에 "OO님이 거래를 신청했습니다 [수락] [거절]" 팝업이 먼저 뜨고,
  신청한 쪽은 "응답을 기다리는 중..." 표시만 봅니다. **상대가 수락해야만
  그제서야 양쪽 화면에 동시에** 거래창이 열립니다 — 거절하면 신청한 쪽에
  거절 토스트만 뜨고 거래창은 열리지 않습니다. 거래창이 열리면 각자 자기
  인벤토리 칸을 클릭(또는 드래그)해서 "내 제안" 칸(최대 9개)에 아이템을
  담고, 상대가 무엇을 제안했는지도 실시간으로 보입니다. 제안 내용이 바뀌면
  **양쪽의 승낙 상태가 자동으로 초기화**됩니다 — 한쪽이 이미 승낙한 뒤에
  몰래 제안을 바꿔치기하는 걸 막기 위해서입니다.
  **양쪽 다 승낙하면 곧바로 성사되지 않고, 5초(`TRADE_CONFIRM_DELAY_MS`)의
  취소 유예가 시작됩니다** — 거래창에 남은 시간이 표시되고, 그 사이 누구든
  승낙 버튼을 다시 눌러 취소하면 자동 성사가 취소되고 협상 상태로 돌아갑니다.
  5초 동안 아무도 취소하지 않아야 그제서야 실제로 아이템이 인벤토리를
  오갑니다. 아이템은 거래가 완전히 끝날 때까지(유예 시간이 다 지날 때까지)
  원래 주인의 인벤토리에 그대로 남아 있습니다(제안만 걸어둔 상태로는 빠지지
  않습니다). 상대가 방을 나가면(응답 대기 중이었더라도) 거래는 자동으로
  취소·정리됩니다.
- **선물 주기**: 거래창 없이, 인벤토리에서 아이템 하나를 골라 바로 상대에게
  건네줍니다. 받는 쪽은 즉시 인벤토리에 아이템이 생기고 토스트로 알림을
  받습니다. (신청→수락 단계나 취소 유예 없이 곧바로 전달됩니다 — 거래보다
  훨씬 가벼운 "그냥 주기" 기능이라서요.)

### 신뢰 경계 — 거래도 솔직하게

> 위 PvP 신뢰 경계와 같은 성질의 한계입니다.

- **서버는 거래 내용을 검증하지 않고 그대로 중계만 합니다.** "내가 정말 그
  아이템을 가지고 있는지", "수량이 맞는지"는 순전히 각 클라이언트가
  보고하는 값을 믿습니다 — 서버(`server/state.ts`)는 인벤토리 자체를 전혀
  모릅니다. 그래서 이론상 개발자 도구로 클라이언트를 조작하면 가지고 있지
  않은 아이템을 제안하는 것처럼 상대 화면에 보이게 만들 수 있습니다.
- 다만 서버가 확실히 막는 것들은 있습니다: **자기 자신과 거래**, **이미 다른
  거래 중이거나 다른 신청에 응답 대기 중인 상대에게 걸기**(`busy` 거부 —
  신청을 보냈지만 아직 상대가 수락/거절하지 않은 상태도 포함), **다른 방
  사람과 거래**(`different_room` 거부), **없는 상대에게 선물**
  (`not_connected`로 알려줌 — 이 경우 보낸 쪽 인벤토리에서 빼면 안 된다는
  신호로 씁니다). 신청한 쪽이 응답을 기다리는 동안 상대가 방을 나가면(또는
  반대로 응답 대기 중에 신청한 쪽이 나가면) 남은 쪽에게 `partner_left`로
  알려서 팝업이 화면에 그대로 남지 않게 합니다. 그리고 완료
  시점의 아이템 이동은 서버가 중계한 상대 값이 아니라 **내가 로컬에서 계속
  추적하고 있던 내 제안 내용**을 기준으로 적용하기 때문에, 네트워크 왕복
  지연과 무관하게 즉시·정확하게 처리됩니다.
- PvP와 마찬가지로, 정말로 부정거래를 막아야 한다면 인벤토리 자체를 서버
  권위로 옮겨야 합니다 — 지금은 "같은 방 친구끼리 편하게 아이템을 주고받는"
  용도에 맞춘 얇은 중계 레이어입니다.

### 무엇이 동기화되나

### 검증

`scripts/e2e.mjs`의 "멀티플레이 · PvP" 절에서 실제 서버 프로세스를 띄우고
브라우저 세 개(해적 하나, 해군 하나, 같은 편 해적 하나)를 각각 접속시켜
확인합니다: 서버가 실제로 뜨는지, 두 클라이언트가 서로를 실제로 인식하는지
(presence), **PvP 체크박스가 접속만 해도 기본으로 켜져 있는지**, 껐다 다시
켜는 토글이 서버까지 실제로 반영되는지, 좌클릭 근접 공격을 날리면 **상대
화면의 체력이 실제로 줄어드는지**(서버 재계산 경로 전체가 진짜로 동작하는지),
공격자 화면에 피해 토스트가 뜨는지, 그리고 **해적끼리는 같은 진영이어도
실제로 피해가 들어가는지**까지 두 브라우저로 직접 확인합니다. 반대로
**해군끼리는 여전히 `same_faction`으로 거부되는지**는 실제 브라우저 대신
`scripts/verify-logic.mjs`의 "PvP: 해적은 서로 싸울 수 있지만 해군은 여전히
안 됨" 절에서 `server/state.ts`를 가짜 소켓으로 직접 두드려 훨씬 빠르게
검증합니다. 이어서
"멀티플레이 — 몬스터(NPC) 동기화" 절에서 한쪽이 어그로 끈 몬스터를 다른 쪽이
실제로 화면에 그리는지(원래는 너무 멀어서 안 보여야 할 몬스터가 유령 덕분에
보이는지, 좌표가 정확히 일치하는지)까지 확인합니다. 이어서 "멀티플레이 —
P2P 거래·선물" 절에서 다른 플레이어에게 실제로 마우스를 올려 테두리 효과를
확인하고, **실제 마우스로 우클릭**해서 메뉴를 띄우고(드래그로는 안 뜨는지도
회귀 테스트), 거래하기를 눌러도 **곧바로 거래창이 열리지 않고 상대에게만
신청 팝업이 뜨는지**, 거절하면 신청한 쪽에 거절 토스트만 뜨고 거래창은 안
열리는지, **수락 버튼을 실제로 눌러야** 그제서야 양쪽 다 거래창이 열리는지
확인합니다. 그다음 양쪽 인벤토리 칸을 **실제로 클릭**해서 제안에 담고, 상대
화면에 그 제안이 실시간으로 뜨는지 확인한 뒤, 양쪽 다 승낙 버튼을 눌러도
**곧바로 성사되지 않고 5초 취소 유예 카운트다운이 뜨는지**, 그 안에 한쪽이
승낙을 취소하면 원래 마감 시각이 지나도 성사되지 않는지, 다시 승낙하고
**이번엔 아무도 취소하지 않고 5초를 실제로 기다려야** 그제서야 성사되어
**실제로 아이템이 서로의 인벤토리를 오가는지**(준 쪽에서는 빠지고 받은
쪽에는 생기는지)까지 전부 실제 브라우저 클릭과 실제 시간 경과로 확인합니다.
선물도 같은 방식으로 상대 인벤토리에 실제로 아이템이 생기는지 확인합니다.
방 나누기, 몬스터 중계, 거래 신청·수락/거절·5초 취소 유예·선물 중계의 서버
로직 자체는 `scripts/verify-logic.mjs`가 진짜 WebSocket 없이(가짜 소켓)
900여 개 순수 로직 검증의 일부로 빠르게 확인합니다(5초 유예 관련 검증은
실제로 5초씩 두 번 기다려 확인하므로 이 스크립트 실행 시간이 조금 늘어납니다).

## 구조

시뮬레이션(게임 로직)과 렌더링(Three.js)을 의도적으로 분리했습니다. 원래는 "나중에 서버
권위 멀티플레이로 확장할 때 렌더러를 갈아끼우기 쉽도록" 하려는 대비였는데, 이제 그 나중이
와서 `simulation/CombatSystem.ts`와 `ShapeMath.ts`가 실제로 `server/`에서도 그대로 돌아갑니다
(자세한 내용은 위 "멀티플레이 · PvP" 절 참고). 다만 몬스터·퀘스트·상점·항해 같은 나머지
시스템은 여전히 각 클라이언트에서 로컬로만 동작하는 싱글플레이어 로직입니다 — 서버로 옮긴 건
"다른 플레이어의 존재를 인식하고 PvP를 판정하는" 얇은 레이어뿐입니다.

  세이브를 먼저 심어두고 개발자 모드로 들어가도 **그 세이브를 읽지 않고** 만렙으로
  시작하는지, `isCloud`가 false라서 **랭킹에 올라가지 않는지**.

두 스위트 모두 콘솔 에러 0건으로 통과합니다.

## 3D 아트 에셋을 추가하고 싶다면

이 프로젝트는 **Three.js**로 만들어져 있어서, Three.js의 표준 로더가 지원하는 형식이면 뭐든
가져올 수 있어요. 그중에서 **glTF 2.0 바이너리(.glb) 파일 하나**로 주시는 걸 추천합니다.

**왜 .glb인가:**

- `GLTFLoader`가 네이티브로 지원하고, 웹용으로 설계된 포맷이라 파일 크기 대비 로딩이 빠릅니다.
- 메시 + 텍스처(PBR) + 스켈레톤 + 애니메이션 클립까지 파일 하나에 다 들어갑니다.
  (.gltf는 텍스처가 별도 파일로 분리되는 버전이라, 파일을 여러 개 주고받지 않으려면 .glb가 편합니다.)
- Blender, Mixamo, Sketchfab 등 대부분의 3D 툴이 glTF 내보내기를 지원합니다.

**FBX나 OBJ로 주셔도 되나요?** 가능은 합니다(`FBXLoader`/`OBJLoader`). 다만 OBJ는 애니메이션을
담지 못하고 FBX는 웹에서 상대적으로 무거워서, 움직이는 에셋은 glTF 변환을 권장합니다.
Blender에서 FBX를 열어 glTF로 다시 내보내는 건 몇 번의 클릭이면 됩니다.

**에셋 체크리스트:**

1. 파일 형식: `.glb` (텍스처 임베드된 바이너리 glTF)
2. 스케일: 1 유닛 = 1미터 (캐릭터는 대략 1.8~2m 높이)
3. 캐릭터라면 Mixamo 스타일 스켈레톤 + 애니메이션 클립(Idle/Walk/Run/Jump/Attack)
4. 캐릭터 1개당 1만 폴리곤 이하 권장
5. 텍스처는 2048x2048 이하, 파일에 임베드

파일을 주시면 `public/models/`에 넣고 `GLTFLoader`로 불러와서 지금의 블록형 플레이스홀더를
교체하는 작업을 도와드릴게요.
